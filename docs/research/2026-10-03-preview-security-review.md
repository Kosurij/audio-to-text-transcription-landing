## Изменения этой проверки

- Обновлены Express 4.22.3, express-rate-limit 8.7.0, Multer 2.4.0 и затронутые транзитивные зависимости. Перед обновлением backend npm audit --omit=dev: 10 записей (8 high, 2 moderate), после: 0. Число advisory-записей не равно количеству доказанных эксплойтов конкретного маршрута.
- Исправленные версии закрывают известные DoS в multipart и проблему нормализации IPv4-mapped IPv6 в ограничителе. Нормализация одинакового IP в разных представлениях проверяется тестом квот.
- Лимит всего HTTP-тела: размер файла + 64 KiB на multipart. Content-Length проверяется до квот/декодирования; chunked-поток ограничивается по фактически принятым байтам. При превышении поток обрывается, а не читается до конца.
- Загрузка без новых байтов завершается через 15 секунд, абсолютный предел загрузки остаётся 90 секунд. Удаление временных файлов и освобождение единственного processing slot проверяются реальными локальными HTTP-соединениями.
- FFmpeg больше не наследует серверные ключи/API/DB environment: только PATH, LANG и LC_ALL. Тестовый дочерний процесс подтверждает отсутствие синтетического секрета. Ограничены отдельные выделения памяти (64 MiB), probing (5 MiB / 5 секунд) и потоки декодера (2). Это дополнительные границы, не полноценная OS-песочница или общий RSS-лимит.
- Во frontend разделены AbortController конфигурации и транскрибации: поздний init больше не перехватывает контроллер активной загрузки. Удаление во время обработки по решению пользователя по-прежнему заблокировано.
- Astro обновлён до 7.3.5 и обновлены затронутые зависимости. Требование Node поднято до >=22.19.0 из-за undici; системный Node не менялся. Сборка проверена отдельно на Node 24.21.0.

## Что ещё требуется перед production

1. Проверить реальную цепочку Caddy → backend и недоступность backend-порта извне. Репозиторий публикует 3002 только на 127.0.0.1 и доверяет одному прокси; тест модели не заменяет проверку фактического deployment.
2. Проверить конкретный FFmpeg/Alpine образ и ограничения CPU/RAM/disk на сервере. Декодер всё ещё работает тем же OS-пользователем в общем backend-контейнере; минимальное окружение не лишает его доступа к файловой системе. Изоляция отдельным worker/container с ограничением сети — следующий шаг для повышенной защиты.
3. Единственный активный запрос ограничивает расходы, но открытый endpoint остаётся чувствителен к намеренному занятию слота и смене IP. CORS не является аутентификацией. Для масштабирования нужны общая admission control и защита на reverse proxy/edge; текущий вариант рассчитан на один процесс.
4. Проверить сбои настоящего Postgres/сетевые таймауты, рестарт процесса посреди резервирования и наблюдаемость QUOTA_REFUND_FAILED. При crash после резерва IP-время может остаться занятым до UTC-сброса; система консервативно ограничивает расход, а не гарантирует exactly-once/refund после crash.
5. Уточнить общий бюджет 100 минут на сайт перед открытым трафиком: он независим от 60 минут на IP и может закончиться раньше индивидуального лимита.
6. Остаточный frontend advisory: http-cache-semantics GHSA-ch52-4w7c-c8xp (нет опубликованного patch). npm audit показывает 3 high-узла одного источника (http-cache-semantics → astro → @astrojs/vue). Не применяли предложенный downgrade Astro до 2.x. Сейчас output=static; библиотека импортируется в assets/build/remote.js, не обслуживает кеш персональных ответов сайта. `/web` возвращает Cache-Control: no-store. Пересмотреть при переходе на SSR/кеширование авторизованных ответов; dev/preview сервер не публиковать наружу.
