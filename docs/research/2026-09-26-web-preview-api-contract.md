# Веб-проба: контракт API и ограничения

Дата: 26.09.2026. Контракт следующего этапа разработки. Код endpoint, настройка production и подключение формы ещё не выполнены. Владелец подтвердил стартовые лимиты: файл до 25 MiB, первые 60 секунд, 3 попытки с одного IP в сутки и общий потолок 100 минут распознавания в сутки. Внутренние таймауты и параллелизм ниже — предложенные технические настройки.

Основа UX: [сценарий веб-демо](2026-09-26-web-demo-design.md).

## Подтверждённая основа в коде

Backend находится в соседнем репозитории `audio-to-text-transcription/backend`. Express уже принимает аудио на диск, использует ffmpeg и PostgreSQL. Провайдер вызывается через `TranscriptionProvider.transcribe(buffer, options)`.

- `middleware/validation.ts`: текущая загрузка принимает до 600 MiB перед проверкой прикладного лимита 500 MiB; её нельзя подключать к веб-пробе без отдельного ограничения.
- `services/transcription.ts`: фабрика может включать fallback Groq → OpenAI.
- `services/grokTranscription.ts`: SDK настроен с одним автоматическим повтором и таймаутом 60 секунд.
- `services/audioPreprocessing.ts`: существующая обработка не является гарантированной обрезкой до первой минуты.
- `utils/ffmpegConcurrency.ts`: уже есть общий лимит процессов ffmpeg. Веб-путь должен его соблюдать.
- `services/database.ts`: доступны pool и транзакции для атомарного учёта лимитов.
- `index.ts`: текущая транскрибация использует fingerprint, необязательную Monetize-идентичность и квоты расширения. Веб-проба получает отдельную цепочку middleware.
- Лендинг уже обращается к `https://api.audio-to-text-transcription.com/contact`; новый маршрут размещается на том же API-хосте.

## Стартовые настройки

| Ограничение | Предложение | Причина |
| --- | --- | --- |
| Распознаваемый фрагмент | Первые 60 секунд | Согласованный бесплатный результат |
| Загрузка | Один файл, до 25 MiB (26 214 400 байт) | Отдельный предел сети и диска; оригинал может быть длиннее минуты |
| Попытки | 3 принятые попытки с одного IP за календарный день UTC | Простое ограничение анонимной пробы |
| Общий запас | 100 вызовов провайдера в день, каждый максимум на минуту | Верхняя граница 100 минут аудио, включая неудачные вызовы |
| Параллельная веб-обработка | Одна на backend-процесс, без очереди | Первоначально щадящий режим для действующего сервиса |
| Входящие POST | Не более 10 в минуту на IP, дополнительно к общему лимитеру | Ограничивает повторные и невалидные запросы |
| Передача файла | До 90 секунд | Ограничение долгих незавершённых загрузок |
| Декодирование | До 20 секунд выполнения, ожидание общего ffmpeg-слота до 5 секунд | Защита CPU и времени ответа |
| Запрос к провайдеру | До 45 секунд, без автоматических повторов и fallback | Один принятый платный вызов на пробу |

Все значения задаются серверной конфигурацией. По умолчанию `WEB_PREVIEW_ENABLED=false`; production включается только после проверки пути. Изменение настроек веб-пробы не меняет лимиты расширения.

IP — приближение к посетителю: пользователи одной сети делят квоту, смена сети позволяет обойти её. Общий постоянный суточный потолок ограничивает расход независимо от этого. На первом этапе не добавляем обязательную регистрацию или CAPTCHA; при подтверждённом злоупотреблении защиту пересматриваем по данным.

## Контракт

### `GET /web/preview-config`

Возвращает `enabled`, `maxFileBytes`, `previewSeconds`, `dailyAttempts`, `resetTimezone: "UTC"` и `supportedExtensions`. Клиент берёт из ответа ограничения для подписи и валидации, а не хранит вторую независимую копию. Endpoint не возвращает глобальные остатки квоты и ключи. Ответ `Cache-Control: no-store`.

Список первой версии совпадает с 14 форматами продукта: flac, mp3, m4a, mpeg, mpga, ogg, opus, wav, aac, wma, webm, mov, mp4, m4v. Фактическое декодирование проверяется для каждого формата до публикации.

### `POST /web/transcribe-preview`

- `multipart/form-data`, ровно одно поле файла `audio`.
- Регистрация, Monetize-токен и `X-User-Fingerprint` не нужны.
- Клиент не выбирает модель, смещение, длительность, background-режим или URL файла. Неожиданные поля отклоняются.
- Только разрешённые origin сайта; localhost разрешён только в development. CORS не считается защитой от прямых серверных запросов.
- Используется отдельный diskStorage с UUID-именами без оригинального имени файла, ограничением 25 MiB и количеством multipart-частей.
- Проверяются расширение и декодируемая аудиодорожка; MIME браузера не заменяет проверку файла. Пустой MIME/octet-stream допустим только при разрешённом расширении и успешном ограниченном декодировании.

Ответ `200`, пример формы данных, а не настоящий результат распознавания:

```json
{
  "requestId": "server-generated-uuid",
  "text": "Example transcript text.",
  "processedSeconds": 60,
  "previewSeconds": 60,
  "hasMoreAudio": true,
  "attemptsRemaining": 2,
  "resetsAt": "2026-09-27T00:00:00.000Z"
}
```

`processedSeconds` определяется подготовленным PCM-фрагментом, а не присланной клиентом длительностью. `hasMoreAudio` вычисляется по наличию декодируемого аудио после 60-й секунды; общую длительность записи для первой версии не обещаем. Если провайдер вернул пустой текст, возвращается `422 NO_SPEECH_DETECTED`; это не гарантия обнаружения любого случая тишины моделью.

Результат: `Cache-Control: no-store`. Текст используется только в текущем ответе; сервер не сохраняет его в БД или общем кэше. Клиент отображает его как обычный текст, без HTML-интерпретации.

Ошибка имеет единый вид:

```json
{
  "requestId": "server-generated-uuid",
  "code": "DAILY_PREVIEW_LIMIT",
  "message": "Today's free preview limit has been reached.",
  "retryAfterSeconds": 3600
}
```

| HTTP | Коды | Поведение клиента |
| --- | --- | --- |
| 400 | INVALID_REQUEST, EMPTY_FILE | Исправить выбор файла |
| 403 | ORIGIN_NOT_ALLOWED | Объяснить недоступность отправки с этой страницы |
| 413 | FILE_TOO_LARGE | Показать предел размера и предложение расширения |
| 415 | UNSUPPORTED_FORMAT | Показать разрешённые форматы |
| 422 | INVALID_AUDIO, NO_AUDIO_TRACK, NO_SPEECH_DETECTED | Объяснить причину, разрешить новый файл |
| 429 | REQUEST_RATE_LIMIT, DAILY_PREVIEW_LIMIT | Показать время повторной попытки; установить Retry-After |
| 503 | PREVIEW_DISABLED, PREVIEW_BUSY, PREVIEW_CAPACITY_REACHED, PREVIEW_UNAVAILABLE | Оставить понятный путь к расширению; не объявлять превышенной личную квоту |
| 504 | PREVIEW_TIMEOUT | Дать ручной повтор; не перезапускать автоматически |

`retryAfterSeconds` и Retry-After возвращаются только при известном сроке. Не показываем отсчёт до восстановления провайдера, который не можем знать.

## Обработка и учёт

1. Проверить флаг, origin, лимит входящих запросов, доступность веб-слота и предварительно квоты до приёма большого тела.
2. Принять один ограниченный файл на диск. Веб-слот занят уже на время загрузки; при занятости — быстрый PREVIEW_BUSY, без накопления ожидающих файлов.
3. Проверить multipart и базовые свойства. Атомарно зарезервировать попытку IP в PostgreSQL перед запуском декодирования. Предварительная проверка из шага 1 не заменяет эту операцию. Ошибка декодирования расходует попытку, но не бюджет провайдера.
4. Через общий ffmpeg-семафор декодировать не более 61 секунды первой аудиодорожки в 16 kHz mono signed 16-bit PCM. Вывод ограничить по времени и размеру; сетевые протоколы и внешние ссылки контейнера запрещены. Форматы ограничиваются разрешёнными самодостаточными контейнерами. Процесс запускается без shell и с контролируемыми аргументами.
5. По числу PCM-сэмплов определить `hasMoreAudio`; собрать WAV только из первых 960 000 сэмплов (60 × 16 000). Сверхлимитный хвост используется лишь для определения наличия продолжения, не отправляется провайдеру и не оплачивается как транскрибация. Число сэмплов, а не container.duration, обеспечивает жёсткий предел.
6. Атомарно зарезервировать один из 100 глобальных вызовов текущего UTC-дня непосредственно перед платным запросом. При исчерпании вернуть PREVIEW_CAPACITY_REACHED. Резерв не возвращается после начала отправки, даже при таймауте, разрыве соединения или ошибке: провайдер мог выполнить обработку.
7. Вызвать Groq `whisper-large-v3-turbo` отдельным экземпляром с `maxRetries=0`, без обёртки fallback, только с подготовленным WAV и синтетическим именем `preview.wav`. Настройки действующего расширения сохраняются.
8. Вернуть результат; удалить исходник и промежуточные файлы в finally, освободить слот. При отключении клиента прервать локальную обработку и запрос через AbortSignal, не обещая отмену уже выполненной услуги провайдера.

Не использовать текущий pipeline chunking/preprocess для всего оригинала перед обрезкой. Общий дневной потолок хранится в БД и не обнуляется перезапуском процесса. При недоступной БД веб-проба закрывается с 503, не переключается на неограниченный режим.

Начальная модель параллелизма предполагает существующий одиночный backend-процесс. При запуске нескольких реплик требуется общий admission-лимит; дневные счётчики уже должны оставаться атомарными между репликами.

## Счётчики и очистка

Отдельная таблица `web_preview_daily_usage`: UTC-дата, тип счётчика (`ip_attempt` или `provider_call`), ключ и used. Уникальность по (дата, тип, ключ); инкремент с проверкой предела выполняется атомарно. IP нормализуется с учётом IPv6 и хешируется HMAC с отдельным серверным секретом. Клиентский fingerprint не принимается. Для глобального счётчика фиксированный ключ.

Записи удаляются после окончания окна плюс 48 часов. В этой таблице нет текста, аудио, имени файла и данных аккаунта. Новая таблица создаётся добавочно; нельзя запускать разрушительное пересоздание существующих таблиц пользователей и платежей.

Временные файлы веб-проб находятся в отдельном подкаталоге. Кроме finally нужна очистка оставшихся после аварии файлов старше 15 минут при старте и каждые 5 минут. Активные файлы исключены из очистки. Сроки должны быть проверены до появления обещаний об удалении в интерфейсе и privacy policy.

Логи и аналитика веб-пути: requestId, стадия, длительность обработки, размер, код ошибки. Не передавать аудио, текст, оригинальное имя файла и содержимое upstream-ошибок, способное их включать. Проверить также автоматические HTTP/error-логи, а не только явные logger-вызовы.

## Повторы и клиент

Первая версия не хранит расшифровки ради idempotency-кэша. Кнопка блокируется на время запроса, SDK и клиент не повторяют запрос автоматически. Ручная повторная отправка — новая попытка; при потерянном ответе предыдущая обработка могла израсходовать лимит. Текущий успешный текст сохраняется в памяти страницы при последующих ошибках, чтобы его можно было скопировать.

Перед запуском видны лимиты и короткая ссылка на правила обработки данных. Отправка файла только после явного Transcribe. Копирование и TXT содержат только реальный доступный текст. Для мобильных устройств предложение расширения поясняет необходимость Chrome на компьютере, не блокируя веб-результат.

## Стоимость и ограничения оценки

В [документации Groq](https://console.groq.com/docs/speech-to-text) на дату проверки указаны $0.04 за час для whisper-large-v3-turbo и минимум 10 оплачиваемых секунд на запрос. При 100 вызовах по 60 секунд арифметический потолок распознавания по этому тарифу — около $0.067 за UTC-день, около $2 за 30 дней. Это не общий бюджет сервиса: трафик, хранение, CPU, налоги, условия аккаунта и изменение тарифа сюда не входят. Для проекта это ориентир, не проверка фактического счёта production.

Настройка 100 вызовов — прежде всего осторожный эксплуатационный старт, а не необходимость из-за высокой цены минуты. При подтверждённом спросе потолок можно поднять без изменения интерфейса. Окна календарные: около полуночи возможно использование двух дневных квот подряд.

Технические источники: [FFmpeg: ограничения длительности](https://ffmpeg.org/ffmpeg.html#Main-options), [Groq: speech-to-text](https://console.groq.com/docs/speech-to-text). Подход с ограниченным PCM-фрагментом — наше проектное решение.

## Критерии проверки перед включением

- Записи 30, 60 и 180 секунд: провайдер получает соответственно не больше 30, 60 и 60 секунд; continuation отсутствует у коротких файлов.
- Контейнер без duration обрабатывается без распознавания всего файла; ложная duration не обходит лимит.
- Каждый из 14 форматов, повреждённый файл, видео без аудио, пустой файл и загрузка сверх размера.
- Параллельные запросы не превышают IP/global-предел; перезапуск не сбрасывает счётчики; граница UTC-дня предсказуема.
- Ошибки, отключение клиента и таймауты завершают дочерние процессы, освобождают слоты и удаляют файлы. Нет автоматического второго вызова или fallback.
- Веб-проба не меняет баланс, историю, очередь и поведение транскрибации расширения.
- Форма доступна с клавиатуры и на мобильном; текст можно скопировать/скачать без установки. Аналитика не содержит пользовательского контента.
- До production согласованы стартовые настройки, обновлены фактические сведения об обработке данных и проверена инфраструктура ограничения тела запроса/времени на прокси.
