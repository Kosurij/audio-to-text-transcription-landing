# Воронка: что уже измеряется и чего не хватает

Дата: 26.09.2026. Основание: локальный код лендинга и расширения, публичный HTML. Настройки целей в кабинете Метрики и доставка событий в Amplitude не проверены.

## Цель

Отдельно оценивать органическое привлечение, переход в магазин, установку, первый полезный результат и покупку. Клик не считать установкой; открытие страницы оплаты не считать покупкой. Цифр конверсии пока нет.

## Существующие сигналы

| Этап | Что уже есть | Ограничение |
|---|---|---|
| Посещение лендинга | Яндекс.Метрика 105283733 в Layout, trackLinks и webvisor | Кабинет и цели неизвестны; блокировщики и согласия влияют на полноту |
| Клик установки | Ссылка в Chrome Web Store с одинаковыми utm_source=site и utm_medium=cpc | Нет явного reachGoal и различения мест CTA; cpc не описывает обычный переход с сайта |
| Новая установка | Production-ветка onInstalled открывает /welcome/ | Страницу можно открыть вручную; её просмотр — вспомогательный сигнал, не достоверный счётчик установок |
| Открытие расширения | extension_started в Amplitude | Повторные открытия не равны новым установкам |
| Синхронная расшифровка | transcription_finished, result=success | Событие с result=queued не означает готовый текст |
| Завершение фоновой расшифровки | background_job_action, action=completed | Отдельное событие; клиент должен получить состояние завершения через polling |
| Просмотр результата | result_viewed | Полезный дополнительный сигнал; не считать каждый повторный просмотр новой активацией |
| Копирование/экспорт | result_action и history_item_action | Повторные действия пользователя; названия/параметры уточнять при настройке отчёта |
| Покупка через интерфейс | checkout_flow с терминальным result=completed | Сверять с серверным подтверждением платежа и выданным тарифом; браузерный успех сам по себе не является выручкой |

## Первая предлагаемая доработка лендинга

Добавить одно событие Метрики `install_click`, с заранее заданными параметрами:

- `placement`: navigation, hero, upload_card, record_card, pricing, footer_cta;
- `plan`: free/basic/pro/max только для тарифных карточек;
- `page_path`: pathname без строки запроса.

Событие вызывается при реальном клике. Навигация должна работать без Метрики, при её блокировке и при ошибке трекера. Не задерживать открытие магазина ради аналитики. Не отправлять произвольные query-параметры, аудио, текст расшифровок, email или имена файлов.

Входной канал измеряется на стороне визита Метрики. Исходящая ссылка в магазин может отдельно маркировать переход с сайта и положение CTA, например utm_source=website, utm_medium=referral, utm_campaign=landing, utm_content=hero. Это проект схемы, не уже внедрённая настройка. Поддержку этих измерений в текущем кабинете CWS проверить перед использованием в отчёте.

Не переносить входящий utm_source поверх источника website: иначе нельзя различить первоначальное привлечение на сайт и дальнейший переход с сайта в магазин. Старую и новую схему пометить датой изменения для корректного сравнения.

Основание реализации события: [документация Метрики reachGoal](https://yandex.com/support/metrica/en/objects/reachgoal). Цель с соответствующим идентификатором необходимо проверить/настроить в кабинете.

## Какие отчёты нужны

1. Конверсия лендинга: визиты с хотя бы одним install_click / подходящие визиты, отдельно organic, страна, устройство, посадочная. Количество кликов дополнительно, а не в числителе конверсии визитов.
2. Магазин: просмотры карточки и установки по доступным в CWS измерениям; период и часовой пояс фиксируются. [Chrome Web Store описывает отчёты установок и удалений](https://developer.chrome.com/docs/webstore/metrics).
3. Активация продукта: первое наблюдаемое успешное завершение для идентификатора пользователя — объединение sync success и background completed. Не включать queued, cancelled и failure. Если история аналитики ограничена, писать «первая наблюдаемая», а не «первая за всё время».
4. Полученная польза: доля новых наблюдаемых пользователей, дошедших до просмотра результата, отдельно от факта завершения обработки. При необходимости добавить копирование/экспорт как второй уровень.
5. Покупки: оплаченные и выданные тарифы по серверным данным. Провайдер по уточнению владельца — Polar через текущую платёжную платформу.

## Где пока нет сквозной атрибуции

По проверенному коду нет подтверждённого общего идентификатора, который связывает визит Метрики, пользователя CWS и fingerprint Amplitude. Нельзя делить все первые расшифровки на посетителей сайта и выдавать это за конверсию конкретного канала: часть установок может приходить прямо из магазина.

Сначала показываем этапы и пробелы отдельно. Сшивка потребует самостоятельной технической проверки механизма установки и передачи источника. Не обещаем её только на основании UTM.

## Порядок эксперимента

Проверить реальные цели/события → внедрить недостающие события кликов → убедиться в доставке на тестовом визите → зафиксировать базовый период → изменить один значимый блок подачи → сравнить сопоставимые периоды с учётом состава трафика. Длину периода и необходимость A/B-теста определить после оценки объёма, не назначать произвольный «статистически значимый» срок.

Это предложение к обсуждению; новые события и цели пока не внедрены.
