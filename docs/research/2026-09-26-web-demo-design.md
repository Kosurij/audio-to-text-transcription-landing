# Бесплатная транскрибация на лендинге: сценарий и референс

Дата: 26.09.2026. Продуктовый сценарий для следующего этапа разработки; endpoint и интерфейс в этом шаге не реализованы.

## Что согласовано с владельцем

- Лендинг должен давать реальную пользу до установки расширения.
- Оставляем загрузку файла; Record убираем из этого блока. Возможность записи в самом расширении остаётся частью его предложения.
- Распознаём и показываем первые 60 секунд, для более короткой записи — её целиком.
- Не оплачиваем распознавание продолжения только для того, чтобы скрыть его блюром.
- Используем отдельный endpoint для сайта на существующем backend.
- За основу пользовательского пути берём Web to PDF.

## Что проверено у Web to PDF

Источники: [лендинг](https://webtopdf.space/) и [Chrome Web Store](https://chromewebstore.google.com/detail/web-to-pdf/pamnlaoeobcmhkliljfaofekeddpmfoh).

По опубликованному содержимому страницы: после вводной части размещён Try Out Demo с вариантами URL, HTML-файл и HTML-код, кнопкой Convert и отдельными Options. Далее описаны получение PDF, инструкция, применение инструмента и расширенные возможности расширения. Это поддерживает последовательность «попробовать → получить пользу → разобраться в дополнительных возможностях».

Число 200 000 отображается в магазине как users, на лендинге — Satisfied Users. Период активности там не указан: WAU и вклад веб-конвертера в рост не установлены.

Граница проверки: текст страницы получен через web-инструмент. Во встроенном браузере сайт завершил загрузку ошибкой таймаута; локальный HTTP-клиент также не смог разрешить домен. Конвертация, экран результата, реальное время ожидания и точное расположение CTA после обработки не проверены. Ниже — наше проектное решение, а не утверждение о реализации конкурента.

## Предлагаемый интерфейс

Одна широкая область загрузки на месте двух текущих карточек, непосредственно после hero. До выбора файла видны назначение, ограничение первой минутой и отсутствие обязательной регистрации. Основная кнопка запускает транскрибацию; установка не требуется для получения результата.

Предлагаемый английский текст:

- Заголовок: **Try audio to text online**.
- Подзаголовок: **Transcribe the first minute of your file for free. No account or installation needed.**
- Область выбора: **Drop an audio or video file here**, кнопка **Choose a file**.
- После выбора: имя файла, размер, **Remove file**, основная кнопка **Transcribe first minute**.
- Результат: **Your transcript**, пояснение **First 60 seconds**, действия **Copy text**, **Download TXT**, **Transcribe another file**.
- Для короткого файла пояснение меняется на **Full transcript**.

Размер и поддерживаемые форматы должны быть видны рядом с выбором файла и совпадать с фактическими ограничениями endpoint. Владелец подтвердил старт: файл до 25 MiB, 3 попытки с одного IP в сутки, общий потолок 100 минут распознавания в сутки. Подробности: [контракт API](2026-09-26-web-preview-api-contract.md).

## Переход к расширению

Для длинного файла под доступной расшифровкой показываем короткую декоративную область продолжения: размытые нейтральные полосы, скрытые от скринридера. Они не содержат выдуманный текст и не изображают уже распознанный скрытый результат.

Надпись: **Need the rest of your recording?**

Пояснение: **Add the Chrome extension, then upload your file there to transcribe the full recording.**

Кнопка: **Add to Chrome**. Дополнительные возможности рядом: запись звука вкладки, история и резюме. Не обещаем автоматический перенос файла, снятие блюра после установки или неограниченную бесплатную обработку.

Для файла до минуты нет блока скрытого продолжения. Предложение расширения можно показать ниже результата как дополнительную возможность, сохранив доступ к полному тексту.

На мобильных устройствах получение текста остаётся самостоятельной пользой. Нельзя обещать установку расширения в мобильный Chrome; адаптация предложения установки входит в техническое проектирование.

## Состояния и доступность

| Состояние | Поведение |
| --- | --- |
| Файл выбран | Видны имя и размер, можно заменить файл; отправка начинается по кнопке |
| Загрузка | Реальный прогресс передачи, если доступен; повторный запуск заблокирован |
| Распознавание | Понятный статус без выдуманного процента и обещаний точного времени |
| Успех | Текст доступен сразу; копирование и TXT не требуют установки |
| Нет распознаваемой речи | Понятное объяснение и возможность выбрать другую запись, без фиктивного текста |
| Неверный формат или превышен размер | Причина и поддерживаемые ограничения рядом с формой |
| Исчерпан лимит | Сообщение о лимите и сроке повторной попытки, если сервер его знает |
| Ошибка сервиса | Возможность повторить действие без автоматических бесконечных запросов |

Выбор файла работает с клавиатуры, статус обработки объявляется через live region, ошибки имеют текстовые подписи. Декоративное продолжение не попадает в скопированный текст или TXT.

## Основа серверной реализации

Предлагаемый маршрут: `POST /web/transcribe-preview`. Он переиспользует существующий провайдер распознавания, но имеет отдельные ограничения и учёт веб-проб. Баланс и идентификатор расширения не используются как способ выдачи публичного пробного доступа.

Ключевое требование: обрезка аудио выполняется на сервере **до обращения к провайдеру**, а не после получения полной расшифровки. Ограничение в клиентском JavaScript недостаточно. Ограничиваются также загрузка, длительность декодирования, параллелизм и суммарное использование сервиса.

До реализации требуется определить конкретные лимиты попыток и общего расхода, механизм защиты публичного endpoint, таймауты и очистку временных файлов. CORS и присланный клиентом fingerprint сами по себе не обеспечивают защиту от повторного использования. Нельзя обещать посетителю сроки удаления или отсутствие передачи данных провайдеру до проверки фактической обработки.

Образец для «Try a sample» допустим только с разрешённой записью и настоящим результатом. Готовый демонстрационный результат можно кэшировать и обозначить как пример, чтобы не оплачивать одинаковое распознавание повторно.

## Что измерять

Выбор файла → запуск → успешная расшифровка → копирование/TXT → клик установки после результата. Отдельно: ошибки, отказы по лимитам и расход на успешную пробу. Имена файлов, аудио и текст в аналитику не передаются.

Клик по установке не равен установке. Успех сценария сначала оценивается по достижению полезного результата; влияние на установки и последующее использование требует доступного измерения. Размер аудитории Web to PDF не доказывает причинный эффект его демо.

## Следующий этап

Спроектировать контракт endpoint и конкретные ограничения на основе существующего backend, затем реализовать форму и серверный путь вместе. Не заменять текущие ссылки формой, которая ещё не умеет вернуть результат. Текущие локальные карточки остаются временным состоянием до готовности настоящего инструмента.
